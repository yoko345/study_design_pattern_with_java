# PR本文作成ルール（学習ブランチ用）

直近の変更差分（`git diff main...HEAD` と `git log main...HEAD`）を確認したうえで、PR 本文を Markdown ファイルとして作成する。

## 出力ルール

- ファイル名は `pr-draft.md` としてリポジトリのルートに作成する
- プレースホルダ・`<!-- -->` コメントは使わず、実内容を書く
- タイトルは自分で判断して決定し、`pr-draft.md` 末尾に別セクションとして提示せず、ファイル先頭に `# タイトル` として直接書く

## 必須セクション（見出し名は固定）

### 概要
何のための PR か、結果として何が変わるかを短く。

### 背景
なぜ必要か。Issue 番号がある場合は `#番号` で参照。

### 変更内容
具体的な差分の説明。ファイルパスや挙動の変化を記載。

※ `/pr` と異なり「動作確認」セクションは含めない。
