# PR本文作成ルール（学習ブランチ用）

直近の変更差分（`git diff main...HEAD` と `git log main...HEAD`）を確認したうえで、ステップ 1 を完了後、ステップ 2〜4 を**確認なし**で順番に実行する。

## ステップ 1: PR 本文ドラフトの作成

- ファイル名は `pr-draft.md` としてリポジトリのルートに作成する
- プレースホルダ・`<!-- -->` コメントは使わず、実内容を書く
- タイトルは自分で判断して決定し、`pr-draft.md` 末尾に別セクションとして提示せず、ファイル先頭に `# タイトル` として直接書く

### 必須セクション（見出し名は固定）

#### 概要
何のための PR か、結果として何が変わるかを短く。

#### 背景
なぜ必要か。Issue 番号がある場合は `#番号` で参照。

#### 変更内容
具体的な差分の説明。ファイルパスや挙動の変化を記載。

※ `/pr` と異なり「動作確認」セクションは含めない。

## ステップ 2: リモートへ push

リモートに push されていないコミットがある場合のみ push を行う。

```bash
git push -q -u origin <現在のブランチ名>
```

## ステップ 3: PR を作成

`pr-draft.md` の内容をもとに `gh pr create` で PR を作成する。タイトルは `pr-draft.md` 先頭の `# タイトル` 行から取り、本文はその行を除いた残り全体を使う。

作成後、`pr-draft.md` を削除する。

## ステップ 4: 完了を報告

作成された PR の URL をユーザーに伝える。
